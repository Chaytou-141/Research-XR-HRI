## ROS2–Unity Connection Startup Steps (Updated for working /joint_states pipeline)

## 1. Navigate to your ROS2 workspace
cd ~/ros2_ws

## 2. Source the ROS2 environment
source install/setup.bash
Note: If your system already auto-sources /opt/ros/foxy/setup.bash in ~/.bashrc, this step may be enough. 
Otherwise, manually source it when opening a new terminal.

## 3. Launch the ROS–TCP Endpoint node
ros2 run ros_tcp_endpoint default_server_endpoint --ros-args -p ROS_IP:=127.0.0.1 -p ROS_TCP_PORT:=10000
- Starts the TCP server that Unity connects to.
- Keep this terminal open while Unity is running.

## 4. Open a second terminal for ROS2 monitoring
cd ~/ros2_ws
source install/setup.bash
Useful monitoring commands:
    ros2 topic list                         # Show all active topics
    ros2 topic info /joint_states           # Get message type, publishers, and subscribers
    ros2 topic echo /joint_states --once    # Inspect one message from Unity
    ros2 topic hz /joint_states             # Check publish frequency

## 5. Run the Unity Project
- Open Unity and load your XR–HRI project.
- Press Play to begin simulation.
- In ROSConnection settings, ensure IP and port match (127.0.0.1:10000).
- Confirm in the ROS terminal that /joint_states appears with Unity as a publisher.

## Unity Publisher Setup (final working version)
- Script: PublishJointStatesStd (publishes sensor_msgs/JointState to /joint_states).
- Joint Articulations: Filled with the 6 ArticulationBody components:
    1. shoulder_link
    2. elbow_link
    3. wrist_pitch_link
    4. wrist_roll_link
    5. wrist_yaw_link
    6. end_effector_link
- Joint Names: Match your URDF exactly:
    a0509_joint_1
    a0509_joint_2
    a0509_joint_3
    a0509_joint_4
    a0509_joint_5
    a0509_joint_6
- Publish Period Sec: 0.1 (≈10 Hz, adjustable).

## Expected Topics When Unity Is Running
- /joint_states – Main topic sending joint angles from Unity to ROS2.
- /chatter – Default ROS test topic (optional).
- /tf – Coordinate frame transformations.
- /parameter_events, /rosout – System-level diagnostics.

## RViz Bring‑Up (Visualize Unity → ROS2 Joint States)

### What RViz is
RViz is ROS’s 3D visualizer. It renders your robot from the URDF (via `/robot_description`) and poses each link using TF transforms produced by `robot_state_publisher` from `/joint_states`. In short: if it moves correctly in RViz, your URDF + joint names + streaming are aligned.

### Why we use RViz right now
- **Ground‑truth check**: Confirms `/joint_states` from Unity are well‑formed and match URDF joint names.
- **TF sanity**: Shows missing transforms (“No transform from …”) immediately.
- **Pre‑MoveIt/Hardware gate**: Validates the whole description/TF pipeline before adding planners or sending commands to a real arm.
